    «(не обновляется)» и полоса «показано расписание от ЧЧ:ММ»; не сегодня — с датой.
    Следствие: лента присылает день раз в минуту, даже если счёт не менялся.

## 3. Решения, которые нужно сохранить

### Видео: прямое окно VK вместо iframe

- **Проблема:** iframe на локальной странице показывал «Видео недоступно»: `video.getEmbed`
  возвращал `error_code: 15, Access denied` с `ref_url=http://127.0.0.1:<порт>/`.
- **Не помогло:** URL с `__ref` и без него, `referrerpolicy="no-referrer"`.
- **Помогло:** официальный `video_ext.php` как самостоятельная страница в отдельном
  `BrowserWindow` — эфир воспроизвёлся (подтверждено снимком изображения, не только API).
  Пустой список элементов `video` не считать признаком неудачи. Точная серверная причина
  отказа iframe не доказана. Не начинать заново диагностику iframe без новой причины.
- **Реализация:** `app.js` → `window.mc.openPlayer` → IPC `player:open` в `main.cjs`
  (только главная страница, `fromMainPage`; только HTTPS `vkvideo.ru`/`vk.com`/`vk.ru`
  и путь `/video_ext.php`). Окно плеера: `sandbox`, `contextIsolation`, без Node;
  посторонние переходы и новые окна — во внешний браузер. Ctrl+клик — эфир в браузере.
- Браузерный режим (iframe, `player.html`/`player.js`) удалён по решению пользователя 14.11.2026.

### Звук и качество прямого плеера

- Решение пользователя: первое окно — 50%, следующие при уже открытых — без звука;
  после закрытия всех следующее снова первое (`player-audio.cjs`).
- Штатный postMessage API VK работает при `js_api=1`, потому что у прямого окна
  `parent === window`: init → inited → set_volume 0.5 → mute/unmute → volumechange.
  До подтверждения окно без звука (`setAudioMuted`); 15 с без ответа — остаётся без звука.
  Ручную громкость после инициализации не перезаписываем.
- «Высокое качество» по умолчанию: публичный API качество не меняет; `preload-player.cjs`
  до скриптов VK записывает `{"type":"high_quality"}` в ключ localStorage
  `vk_player_preferred_default_quality_settings` один раз за запуск. Формат хранилища VK
  недокументирован: при его изменении плеер вернётся к «Автоматически».

### VK: чтение каналов

- Основной способ — API VK Видео анонимным токеном веб-клиента (`vk-api.mjs`); запасной —
  скрытое окно со страницей канала (`page-reader.mjs`, `contextIsolation: false` ради
  перехвата запросов страницы), по одному каналу и с растущей паузой после неудач.
- Догрузки (страницы 2–3) читаются раз в 15 минут; чаще — только пока в них есть эфир,
  который идёт или ожидается в ближайшие 24 часа (порог — решение пользователя).
  На настоящем VK: 15 → 7 запросов за круг при том же числе эфиров.
- Пустой ответ канала почти всегда означает доступ не из России.

### ESPN

- Решение пользователя: ESPN — источник. Запросы через встроенный `fetch` Node.js:
  Chromium/Electron получал 403. VK — через `net.fetch` Chromium. Не объединять эти
  транспорты. Ограничение: ESPN не учитывает системный прокси Windows.
- Мужские/женские сетки на Шлемах разделяются по меткам ESPN (`mens-singles` и т. д.);
  микст не входит. Идущий матч, начатый вчера, остаётся в сегодняшнем дне
  (поведение подтверждено пользователем).
- Уровни турниров — `tournaments.json` по сезонам (решение пользователя: обновлять вручную
  раз в год, источник — Википедия). Нет сезона — показываются все турниры.
  Процедура — `docs/REFERENCE-DATA.md`.

### Диагностический отчёт

- Решение пользователя по составу: версия, ОС, состояние источников, время успешных
  запросов, очищенные ошибки; без путей с именем пользователя, URL с параметрами,
  токенов и содержимого настроек.
- `src/core/diagnostics.mjs`: известные папки → `<userData>`/`~`/`<user>`; имена и подписи
  своих каналов → «свой канал N» по всему тексту и только целым словом (шапка с названием
  приложения не затрагивается); время в UTC. В Electron 44 буфер обмена асинхронный —
  `clipboard.writeText` ожидается.

### Продукт и данные

- Разряды в интерфейсе — «Мужчины»/«Женщины» (решение пользователя); имена игроков —
  английские, как в ESPN; `players.json` нужен только для сопоставления с русскими
  заголовками VK.
- Каналы по умолчанию: `tennisprimesport` «ПраймСпорт», `sportcast_tennis` «Sportcast Теннис»,
  `bbtennis_live` «BB Tennis», `tennis_bolshe` «Больше! Теннис», `tennistimehere` «Теннис Тайм».
- Пары выключены по умолчанию, поддержка сохранена; полное удаление не согласовано.
- Иконка — свой мяч с тёмной обводкой (`scripts/make-icon.ps1`, PNG 256 px, ICO 8 размеров).
- Данные: установленная версия — `%APPDATA%\TennisCenter`, из исходников — `TennisCenter-dev`.
  Обновления — GitHub Releases `eonyushkin-commits/match-center-tennis`.

## 4. Ограничения и открытые вопросы

- **Ждёт подтверждения пользователя:** скрытие Next Gen ATP Finals и всех WTA 125
  (решение агента при введении уровней). Уведомления об избранных на скрытых турнирах
  тоже не приходят.
- ESPN не даёт счёт внутри гейма, статистику, русские имена, челленджеры и ITF.
- Привязка эфиров эвристическая: если соперники играют дважды за двое суток, запись
  первой встречи может привязаться ко второй.
- Трансляции VK доступны только с российского IP.
- Отложено (меняет поведение или требует визуальной проверки):
  - проверка отправителя у IPC `update:*` (у `player:open` и `diagnostics:copy` она есть);
  - список доменов VK в нескольких местах с разной строгостью (`main.cjs`,
    `preload-player.cjs`, `format.mjs` `embedUrl`, CSP в `server.mjs`);
  - опрос VK с полной частотой, когда окно в трее; ESPN раз в минуту для дня без
    идущих матчей; `watch.mjs` сопоставляет эфиры для всех матчей, а не только избранных;
  - вынос окна плеера из `main.cjs`; общие тестовые помощники; кэш Electron в CI.
- Установщик не подписан; установка на чистой Windows и автообновление не проверялись.
- Локальные теги v1.0.0–v1.0.2 унаследованы от футбольного проекта и отличаются от
  удалённых: не отправлять и не использовать. Релизы создаются GitHub с явным SHA.
- Пути в коде и документации — относительные; идентификатор приложения и папку
  настроек не менять из-за имени каталога.
