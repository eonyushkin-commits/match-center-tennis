## 3. Решения, которые нужно сохранить

### VK: видео исправлено прямым окном (14.11.2026)

**Проблема.** И встроенный плеер, и прежняя кнопка «В окне» показывали «Видео недоступно».
Прежнее отдельное окно тоже содержало локальную страницу с iframe — способ загрузки не менялся.
Страница VK отвечала HTTP 200, но запрос `video.getEmbed` возвращал `error_code: 15, Access denied`;
в нём передавался локальный `ref_url=http://127.0.0.1:<порт>/`.

**Что проверено.**

- На одном и том же эфире Sportcast исходный URL с `__ref` и URL без него в iframe
  одинаково показывали ошибку. Сохранение параметра само по себе не устраняло отказ.
- Стандартный `referrerpolicy="no-referrer"` в iframe не помог.
- Прямое открытие официального `video_ext.php` как самостоятельной страницы в Electron
  помогло: `video.getEmbed` вернул `error_code: 0`, снимок окна подтвердил изображение эфира
  Андреева — Шнайдер. Проверено реальное изображение, не только ответ API.
- Обычный поиск HTML-элемента `video` возвращал пустой список даже при видимом изображении;
  это не использовать как единственный критерий успешного воспроизведения.
- Официальная [схема VK](https://github.com/VKCOM/vk-api-schema/blob/master/video/objects.json)
  описывает `player` как готовый URL для встраивания. Страницы dev.vk.com инструментом
  не открылись. Точная серверная причина отказа локальному iframe не доказана.

**Итоговое техническое решение.**

- `src/web/app.js`, `openPlayer`: при наличии Electron-моста `window.mc` клик по каналу
  отправляет запрос `player.html?src=...` через `window.open` и не создаёт iframe в строке.
- `src/electron/main.cjs`, `setWindowOpenHandler`: перехватывает этот запрос и открывает
  отдельный `BrowserWindow`, загружающий официальный HTTPS `video_ext.php` напрямую.
  Проверяются origin/путь локального запроса и домен/путь адреса VK.
- Удалённая страница получает `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`,
  без preload. Посторонние переходы и новые окна отправляются во внешний браузер.
- `src/web/format.mjs`, `embedUrl`: сохраняет параметры официального URL, включая `__ref`.
- Плеер имеет пропорции 16:9 и открывается поверх остальных окон; несколько матчей можно
  смотреть одновременно. Ctrl + клик по каналу открывает эфир во внешнем браузере.

**Ограничения решения.** В Electron нет просмотра внутри строки матча, возврата записи
из окна в строку с той же секунды и старой кнопки переключения «Поверх окон».
Не описывать эти функции как работающие. `player.html`, `player.js`, `opened.mjs` и функции
iframe сохранены для обычного браузера, это используемый код.

### ESPN: отдельный сетевой стек

- Пользователь выбрал ESPN как источник. Chromium/Electron получал 403; встроенный
  `fetch` Node.js принимался. Решение пользователя: использовать Node.js fetch для ESPN.
- `src/electron/main.cjs` передаёт `espnFetch` в `src/core/app.mjs`; для VK остаётся `net.fetch`
  Chromium. Не объединять обратно эти два транспорта при рефакторинге.
- Ограничение: запросы ESPN этим способом не учитывают системный прокси Windows.

### Продуктовые решения и настройки

- Имена игроков на экране английские. `src/core/players.json` нужен для сопоставления
  русских заголовков VK, а не для перевода интерфейсных имён игроков.
- Каналы: `tennisprimesport` → «ПраймСпорт», `sportcast_tennis` → «Sportcast Теннис»,
  `bbtennis_live` → «BB Tennis», `tennis_bolshe` → «Больше! Теннис»,
  `tennistimehere` → «Теннис Тайм».
- Пользователь просил без челленджеров и пар. Челленджеров в источнике нет;
  пары сейчас выключены по умолчанию, но галочки и поддержка сохранены по решению агента.
  Полное удаление пар отдельно не согласовано.
- Посев стоит после флага перед именем; раунд и корт — строкой под турниром, без дубля справа.
- Собственной иконки нет по просьбе пользователя, используется стандартная.
- Обновления направлены на `eonyushkin-commits/match-center-tennis`.
- Отдельные данные: установленная версия `%APPDATA%\TennisCenter`, исходники
  `%APPDATA%\TennisCenter-dev`. Пользовательские настройки не смешивать с футбольным приложением.

### Переход через полночь: текущая логика сохранена пользователем

- `src/core/day.mjs`: матч, который ESPN всё ещё считает идущим, включается в сегодняшний
  день, даже если начался вчера. `src/core/espn.mjs` запрашивает также соседние дни.
- Если матч ESPN уже завершён, а эфир VK продолжается, сам статус эфира не переносит
  вчерашний матч в сегодняшний LIVE. Отдельного списка всех живых эфиров нет.
- Пользователь ответил «ок» на это объяснение; изменение поведения не запрошено.

## 4. Известные ограничения и открытые решения

- ESPN не даёт здесь счёт внутри гейма, статистику, русские имена, челленджеры и обычный
  ITF World Tennis Tour. Большой шлем входит в используемые табло ATP/WTA.
- На Большом шлеме табло atp и wta содержат обе сетки. По последующему разрешению
  пользователя 14.11.2026 buildDay теперь выбирает точный slug: мужские — ATP,
  женские — WTA, отдельно singles/doubles. Микст не входит ни в одну выбранную категорию.
  Отдельного API и определения пола по именам нет. Порядок настроек не меняет категорию.
- Если соперники играют дважды за двое суток, запись первой встречи может привязаться ко второй.
- Игроков вне словаря сопоставляем по латинице или пользовательским вариантам написания.
- VK-каналы проверялись с российским IP. Доступность конкретного эфира может изменяться.
- Полное удаление пар отдельно не согласовано. Сборка, коммит, push и релиз разрешены
  пользователем 14.11.2026 и выполнены.
- Папка ещё имеет старое имя. Переименование в `match-center-tennis` дважды блокировалось
  занятым файлом/каталогом Windows. Виновный процесс точно не установлен;
  связь с терминалом/VS Code/Codex была предположением. Пользователь отложил переименование.

Запросы к сети и данные AppData могут требовать разрешения среды исполнения.
Если Electron мгновенно завершается, проверить singleton/существующий экземпляр,
а не считать код возврата 0 доказательством появления нового окна.
