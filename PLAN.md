## 3. Решения, которые нужно сохранить

### VK: видео исправлено прямым окном (14.11.2026)

**Проблема.** И встроенный плеер, и прежняя кнопка «В окне» показывали «Видео недоступно».
Прежнее отдельное окно тоже содержало локальную страницу с iframe — способ загрузки не менялся.
Страница VK отвечала HTTP 200, но запрос `video.getEmbed` возвращал `error_code: 15, Access denied`;
в нём передавался локальный `ref_url=http://127.0.0.1:<порт>/`.

**Что проверено.**

- На одном и том же эфире Sportcast исходный URL с `__ref` и URL без него в iframe
  одинаково показывали ошибку. Сохранение параметра само по себе не устраняло отказ.
- Стандартный `referrerpolicy="no-referrer"` в iframe не помог.
- Прямое открытие официального `video_ext.php` как самостоятельной страницы в Electron
  помогло: `video.getEmbed` вернул `error_code: 0`, снимок окна подтвердил изображение эфира
  Андреева — Шнайдер. Проверено реальное изображение, не только ответ API.
- Обычный поиск HTML-элемента `video` возвращал пустой список даже при видимом изображении;
  это не использовать как единственный критерий успешного воспроизведения.
- Официальная [схема VK](https://github.com/VKCOM/vk-api-schema/blob/master/video/objects.json)
  описывает `player` как готовый URL для встраивания. Страницы dev.vk.com инструментом
  не открылись. Точная серверная причина отказа локальному iframe не доказана.

**Итоговое техническое решение.**

- `src/web/app.js`, `openPlayer`: при наличии Electron-моста `window.mc` клик по каналу
  отправляет запрос `player.html?src=...` через `window.open` и не создаёт iframe в строке.
- `src/electron/main.cjs`, `setWindowOpenHandler`: перехватывает этот запрос и открывает
  отдельный `BrowserWindow`, загружающий официальный HTTPS `video_ext.php` напрямую.
  Проверяются origin/путь локального запроса и домен/путь адреса VK.
- Удалённая страница получает `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`;
  preload только preload-player.cjs (качество). Посторонние переходы и новые окна отправляются во внешний браузер.
- `src/web/format.mjs`, `embedUrl`: сохраняет параметры официального URL, включая `__ref`.
- Плеер имеет пропорции 16:9 и открывается поверх остальных окон; несколько матчей можно
  смотреть одновременно. Ctrl + клик по каналу открывает эфир во внешнем браузере.

**Ограничения решения.** В Electron нет просмотра внутри строки матча, возврата записи
из окна в строку с той же секунды и старой кнопки переключения «Поверх окон».
Не описывать эти функции как работающие. `player.html`, `player.js`, `opened.mjs` и функции
iframe сохранены для обычного браузера, это используемый код.

### Звук прямого плеера (локальная правка после 1.0.2)

- Требование пользователя: первое открытое окно — 50%, новые при уже открытых — без звука.
  Учёт ведётся отдельным Set только для окон плеера, не включает главное окно и чтение VK.
  Закрытие первого не включает звук в оставшихся; закрытие всех сбрасывает порядок.
- Проверка официального https://vk.com/js/api/videoplayer.js и прямого VK показала:
  self-postMessage работает при js_api=1, потому что у прямого окна parent === window.
  Используются init → inited → set_volume 0.5 → mute/unmute → volumechange.
  Если исходное состояние уже верное, дополнительные команды не нужны.
- До подтверждения нужного состояния действует setAudioMuted(true); затем блокировка
  Electron снимается и звук управляется самим VK. Инициализация ограничена 15 секундами;
  при отказе API окно остаётся без звука, в консоль выводится предупреждение.
  Это ограничение при изменении протокола VK; бесконечного сброса ручной громкости нет.
- Remote-окна с nodeIntegration:false, contextIsolation:true, sandbox:true; preload
  появился позже только для качества (см. ниже). Браузерный iframe и внешние браузеры не менялись.

### Качество прямого плеера (локальная правка после 1.0.2)

- Требование пользователя: при открытии трансляции по умолчанию «Высокое качество».
- Проверено: публичный https://vk.com/js/api/videoplayer.js не имеет команды смены
  качества (только getQuality и событие qualitychange). Бандл плеера (копии в
  dist/vk-quality-*.js) хранит выбор меню в localStorage, ключ
  vk_player_preferred_default_quality_settings; «Высокое качество» — type high_quality
  (нижний предел автовыбора), при отсутствии ключа VK сам записывает auto_quality.
- Техническое решение агента: окно плеера получило preload-player.cjs. Он записывает
  {"type":"high_quality"} до скриптов VK, только на video_ext.php доменов VK и один раз
  за запуск (метка mc_default_quality_seeded; сессия matchcenter живёт в памяти), чтобы
  ручной выбор пользователя в меню не перезаписывался следующими окнами.
  Запись на dom-ready отвергнута: гонка с инициализацией плеера.
- Это меняет прежнее «remote-окна без preload»: preload есть, но sandbox:true,
  contextIsolation:true, nodeIntegration:false сохранены, странице ничего не открывается.
- Ограничение: формат хранилища VK недокументирован; при его изменении плеер просто
  вернётся к «Автоматически». Браузерный iframe не менялся.

### VK API: догрузки раз в 15 минут (локальная правка после 1.0.3)

- Проблема: каждый круг (60 с) читал по каналу 3 ответа — первые 3 видео и две догрузки
  по 20; на 5 каналов 15 запросов в минуту, хотя догрузки почти целиком postlive.
  Пользователь согласился на предложение агента читать их реже.
- Проверено на настоящем VK 14.11.2026: в первом ответе всего 3 видео, а ожидаемые
  (upcoming) эфиры встречаются и в первой догрузке (bbtennis_live, tennis_bolshe).
  Поэтому простой кэш догрузок по времени не годится: начало эфира опоздало бы до 15 минут.
- Техническое решение агента (src/core/vk-api.mjs): полное чтение раз в DEEP_TTL_MS = 15 мин;
  между ними — первая страница плюс догрузки до тех пор, пока в свежих ответах не встретятся
  все started и те upcoming/waiting из прошлого чтения, чьё начало не позже чем через
  24 часа (решение пользователя: дальние ожидаемые эфиры чаще не обновлять; неизвестное
  или прошедшее время начала считается близким). Свежие видео ложатся поверх прошлого
  набора (видео, сдвинутое с первой страницы, не пропадает); полное чтение собирает набор
  заново. Итог на настоящем VK: 15 → 7 запросов за круг, число эфиров то же.
- Ограничение: изменения у завершённых записей в догрузках (удаление, новое название)
  видны с задержкой до 15 минут; кнопка ↻ полное чтение не форсирует.

### Уровни турниров (локально после 1.0.5)

- Требования пользователя 14.11.2026: справочник обновляется вручную раз в год, без
  периодической проверки; источник сейчас — Википедия, позже возможна ссылка на офсайт.
  Есть справочник сезона — показывать только Grand Slam, итоговые (ATP/WTA Finals),
  1000/500/250, уровень в шапке; командные турниры не нужны. Справочника нет — показывать всё.
- Проверено: ESPN отдаёт только `major` (true у Шлемов), уровней 1000/500/250 и 125 нет.
  Календари взяты из wikitext страниц 2026_ATP_Tour и 2026_WTA_Tour (action=raw).
  Все 113 турниров Википедии (59 ATP + 54 WTA без командных и Next Gen) однозначно
  сопоставлены номерам ESPN по названию и городу; скрипт проверил, что каждый номер есть
  в табло нужного тура, не занят дважды и содержит сетку этого пола. Лион у ESPN под двумя
  номерами (110 с сетками и 452 без) — в справочнике оба.
- Техническое решение агента: src/core/tournaments.json — сезон → atp/wta → { id, level, name };
  id — номер ESPN до дефиса, сезон — часть после дефиса. Туры раздельно, потому что у общего
  турнира уровни разные (Брисбен: ATP 250 / WTA 500). day.mjs levelOf: есть сезон — уровень
  или undefined (турнир скрыт); нет сезона — null, у Шлема по `major` — «Grand Slam».
  Уровень — поле league.level; view.mjs рисует метку .level в шапке и в подписи блока
  «Сейчас в эфире»; filter.mjs ищет и по уровню.
- Решение агента, требует подтверждения: Next Gen ATP Finals не показывается (не итоговый
  турнир тура). Скрыты все WTA 125, в том числе Birmingham, Palermo, Warsaw, Newport —
  в календаре Википедии 2026 их нет среди WTA 250/500.
- Следствие: уведомления об избранных игроках на скрытых турнирах тоже не приходят
  (watch.mjs строит тот же день).
- Обновление на следующий год: добавить сезон в tournaments.json. Скрипты разбора wikitext
  и сопоставления — во временной папке сессии, в проект не входят.

## 4. Известные ограничения и открытые решения

- ESPN не даёт здесь счёт внутри гейма, статистику, русские имена, челленджеры и обычный
  ITF World Tennis Tour. Большой шлем входит в используемые табло ATP/WTA.
- На Большом шлеме табло atp и wta содержат обе сетки. По последующему разрешению
  пользователя 14.11.2026 buildDay теперь выбирает точный slug: мужские — ATP,
  женские — WTA, отдельно singles/doubles. Микст не входит ни в одну выбранную категорию.
  Отдельного API и определения пола по именам нет. Порядок настроек не меняет категорию.
- Если соперники играют дважды за двое суток, запись первой встречи может привязаться ко второй.
- Игроков вне словаря сопоставляем по латинице или пользовательским вариантам написания.
- VK-каналы проверялись с российским IP. Доступность конкретного эфира может изменяться.
- Полное удаление пар отдельно не согласовано. Сборка, коммит, push и релиз разрешены
  пользователем 14.11.2026 и выполнены.
- Ограничение переименования папки больше не актуально: текущий рабочий каталог имеет
  имя `match-center-tennis`. Прежние неудачные попытки оставлены в историческом журнале.
  Пути в исходниках и документации должны оставаться относительными к проекту.
- В dist итоговая сборка 1.0.2 с тёмной обводкой опубликована; предыдущие сборки
  в dist/icon-preview устарели. Диагностические PNG, release-notes-1.0.2.md,
  release-verification.json и published-release.json оставлены в игнорируемом dist.
