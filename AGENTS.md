# Правила работы с проектом

## Контекст между агентами

- В начале работы прочитай `PLAN.md`. Это актуальная передача контекста, а не журнал чата.
  При необходимости проверь указанные там файлы и фактическое состояние Git.
- Обновляй `PLAN.md` самостоятельно, без отдельной просьбы пользователя, после значимой
  вехи, принятого решения, существенной неудачной проверки или перед завершением
  незаконченной работы. Для чисто информационного ответа без новых решений запись не нужна.
- Перед существенной реализацией кратко обнови текущую задачу и следующие шаги.
  Не записывай каждый запуск команды, чтение файла, уточнение и мелкую правку.
- Поддерживай разделы: текущая задача, состояние, решения, проблемы и ограничения,
  проверки, следующие шаги, последние вехи. Обновляй существующие записи вместо
  дописывания противоречащих им статусов в конец файла.
- Решение описывай как «проблема → что проверено → что помогло/не помогло → итог».
  Указывай значимые файлы и причину выбора, чтобы другой агент не повторял диагностику.
- Различай факт, гипотезу, решение пользователя и техническое решение агента.
  Не выдавай HTTP 200 или успешный unit-тест за подтверждение воспроизведения видео.
- Для проверок записывай дату, команду, результат и предел проверки. При отсутствии
  свежего прогона пиши «последний известный», а не «всё работает».
- При прерывании оставляй точку продолжения: что сделано, что не закончено, какие
  временные файлы/процессы оставлены и какое следующее действие даст новый результат.
  Не сохраняй в плане токены, cookies, персональные данные или временные подписанные URL.
- Не утверждай, что приложение сейчас запущено, только по записи прошлой сессии.
  Не переносить прошлое разрешение на запуск на коммит, push или публикацию релиза.
- Длинную историю переноси в `docs/HISTORY-*.md` со ссылкой из плана. История не является
  очередью задач: решённые вопросы должны быть закрыты в актуальном `PLAN.md`.

## Проверки и границы очистки

- Команды: `npm test` — ядро и модули страницы, `npm run smoke` — сценарии Electron,
  `npm run app` — приложение, `npm run dist` — установщик.
- После изменения поведения запускай подходящие проверки. После правок только Markdown
  проверяй ссылки и согласованность текста; запуск тестов приложения не требуется.
- Не удаляй браузерный плеер лишь потому, что Electron использует прямое окно VK:
  браузерный режим по-прежнему использует `player.html`, `player.js` и состояние iframe.
- Пути в коде и документации делай относительными к проекту; папка проекта может быть
  переименована. Пользовательские данные установленной версии и dev-профиля разделены.
